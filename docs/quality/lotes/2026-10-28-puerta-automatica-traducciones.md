## Cambio y comportamiento

El controlador resuelve primero el SHA permitido y la existencia de trabajo. Después llama a `translation-preflight.yml` con ese mismo SHA. `wave-1` depende de `ready` y `preflight`; si la puerta falla, faltan ejecutables, un proceso termina por señal o no devuelve un estado válido, no se programan los cuatro jobs de modelos. El vigilante existente clasifica ese fallo como una incidencia accionable aunque el informe anterior indicara cola vacía. No se fuerza un error real ni se envía otro correo de prueba.

`translation-preflight.py` ejecuta completas las suites actuales de semántica/controlador/avisos, veto de errores históricos y refinamientos, procedencia de paquetes/vista previa, y la propia puerta. Después ejecuta las dos suites Node del adaptador y su integración con el HTML real: **45 Python y seis Node**. Se detiene en el primer comando fallido. No carga modelos, instala dependencias, consulta APIs ni escribe memoria real. La prueba de exportación conserva su archivo `GITHUB_OUTPUT` aislado.

Workflow de solo lectura, repositorio público, runner estándar, Python 3.11 y Node de `.node-version`, acciones fijadas por SHA, sin secretos, cachés, artifacts o despliegues. El workflow puede lanzarse manualmente para comprobar este contrato sin relanzar una traducción. Los permisos de escritura del publicador y de incidencias no se amplían. La dependencia obligatoria sigue el mecanismo de [jobs.needs de GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idneeds), mediante [un workflow reutilizable](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows).
