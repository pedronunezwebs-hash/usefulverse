# Criterios de coste cero y vigencia para las 300 herramientas

Fecha: 19 de octubre de 2026. Decisión del propietario: no añadir costes a UsefulVerse en GitHub, Cloudflare, Crossref ni otros proveedores. Cada herramienta debe tener interfaz disponible en los 37 idiomas del producto.

## Coste

- Preferir HTML, CSS, JavaScript, Web Crypto, Canvas, Web Audio, IndexedDB y datos que el visitante aporte. El cálculo y los archivos privados se quedan en su dispositivo.
- No llamar a endpoints de pago, APIs de inferencia alojadas, APIs que necesiten una cuenta facturable, ni servicios cuya gratuidad comercial no esté demostrada. No añadir Workers de API, bases de datos, R2, Durable Objects, Containers, cron o proxies para completar una función.
- Las APIs públicas externas solo se admiten si sus términos actuales permiten el uso comercial con anuncios, no requieren clave o suscripción, exponen el acceso directo desde el navegador y documentan límites compatibles con un uso moderado. Las llamadas se hacen solo después de una acción del visitante, con topes por consulta, timeout, cancelación y atribución. Si no hay límite/coste verificable, la función pasa a modo local o se suspende.
- No descargar pesos en el servidor ni incluir pesos grandes en el despliegue. Una librería o modelo cliente solo se acepta con licencia redistribuible comercial, tamaño y rendimiento medidos, y entrega desde una fuente que no facture a UsefulVerse. No se considera “gratis” una API por tener un tramo gratuito.
- No ejecutar workflows, publicar ramas ni desplegar como parte de esta implementación. Antes de cualquier operación externa se comprobarán las cuotas y el coste máximo según las instrucciones de operación vigentes. Los datos de coste del proveedor pueden cambiar.
- Prohibido usar Crossref como backend, proxy o dependencia de ejecución de una herramienta. Una referencia bibliográfica enlazada no equivale a una llamada de API; aun así, cada herramienta debe usar la fuente primaria más directa que resuelva su función.

## Datos que cambian

- Una herramienta puramente local no requiere una actualización remota para funcionar. Sus reglas y tablas versionadas deben indicar fuente, jurisdicción, ejercicio y fecha de comprobación.
- Para impuestos, prestaciones, empleo, legislación y fórmulas clínicas, usar fuentes oficiales primarias. Incluir `effectiveFrom`, `checkedAt` y `reviewDue` en el registro de mantenimiento. La compilación debe bloquear o desactivar el resultado cuando la regla haya superado `reviewDue`; nunca presentar una tabla caducada como vigente.
- La consulta en vivo a una fuente oficial gratuita se permite únicamente tras comprobar términos comerciales, CORS, privacidad, cuota y ausencia de facturación. Mostrar proveedor y hora de consulta; manejar error y datos ausentes sin inventar valores. No prometer continuidad ni cobertura que el proveedor no garantice.
- Si una fuente no tiene una ruta gratuita, comercial, accesible y con límites verificables, ofrecer entrada/importación local de datos o una explicación fechada que no pretenda estar actualizada. No sustituirla por una cifra inventada ni por un feed no autorizado.
- La actualización automática “siempre” no se puede garantizar sin un proceso recurrente y una fuente estable. No crear un cron ni un workflow para simularlo. La alternativa sin coste de infraestructura es revisar fuentes oficiales antes de cada ejercicio, registrar el cambio y hacer que las herramientas caduquen de forma segura hasta esa revisión.

## 37 idiomas

- Mantener los 37 paquetes estáticos que ya define el proyecto y sus rutas actuales. La disponibilidad del idioma de la interfaz no implica cambiar país, moneda, unidades, jurisdicción o reglas.
- Cada paquete necesita claves completas, cadenas no vacías, placeholders idénticos y revisión de RTL. No contar una cadena inglesa de fallback como traducción.
- La cola local M2M100/MADLAD no usa un proveedor de traducción alojado ni cobra por carácter. Sus salidas son borradores hasta revisión. Ningún borrador puede etiquetarse como aprobado por el propietario o exportarse como aceptación humana sin evidencia de esa revisión.
- Instrumentos clínicos y texto legal con traducciones oficiales requieren la versión autorizada. Si no existe para un idioma, no fabricar una traducción y llamarla oficial; la herramienta debe declarar esa limitación o quedar suspendida en esa ruta.

## Aceptación de una herramienta

1. Hace su tarea descrita con límites reales y pruebas reproducibles.
2. No depende de una llamada facturable, servidor, cuenta, clave o ejecución de terceros que UsefulVerse tenga que pagar.
3. Cualquier dato cambiante tiene fuente primaria, fecha y vencimiento; un fallo o vencimiento no produce una respuesta falsa.
4. Tiene los 37 paquetes completos y cumple el contrato de locale del repo.
5. La privacidad, el coste de datos/red para el visitante, la licencia y la atribución se explican con precisión.
6. La publicación sigue bloqueada si falta evidencia para cualquiera de estos puntos.

## Fuentes revisadas para alternativas sin tarifa

- **MET Norway Locationforecast:** datos meteorológicos globales y licencia de datos compatible con uso comercial. El acceso público no tiene SLA ni capacidad ilimitada; sus términos permiten sitios de bajo volumen que se identifiquen por `Origin`, pidan bajo demanda y respeten caché/`Expires`. No crear un proxy de pago. Si el tráfico de UsefulVerse dejara de ser bajo o el proveedor cambiase términos, apagar la consulta hasta encontrar alternativa. [Términos](https://api.met.no/doc/TermsOfService) · [licencia y datos](https://api.met.no/.License) · [FAQ de cuota](https://docs.api.met.no/doc/FAQ.html).
- **National Weather Service API:** alternativa oficial sin tarifa para cobertura de EE. UU.; tiene límite razonable no publicado y requiere identificar la aplicación. No presentarla como cobertura global. [Documentación oficial](https://www.weather.gov/documentation/services-web-api).
- **Open-Meteo Free API:** excluida del sitio con anuncios, ya que sus condiciones reservan el nivel gratuito a usos no comerciales. Su plan comercial es de pago. [Términos](https://open-meteo.com/en/terms).
- **Cloudflare Static Assets:** la documentación de producto indica que servir assets estáticos no añade coste por petición ni almacenamiento; las solicitudes que invoquen un Worker sí se facturan según Workers. No inferir de esto que el despliegue esté autorizado sin revisar la cuenta, cuotas y facturación actuales. [Facturación y límites](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/).
- **GitHub Actions:** el uso incluido varía por plan y sobrepasarlo puede generar facturación; un presupuesto `Stop usage` debe verificarse antes de disparar workflows. Este trabajo no inicia workflows ni hace push. [Uso incluido](https://docs.github.com/en/billing/reference/product-usage-included) · [presupuestos](https://docs.github.com/en/billing/how-tos/set-up-budgets).

Estas referencias justifican solo las alternativas descritas, no certifican la gratuidad de otros proveedores ni congelan sus condiciones para siempre. Revisarlas de nuevo antes de activar, desplegar o programar consultas.
